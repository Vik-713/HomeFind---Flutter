QUESTION 1: What is the fundamental difference between StatelessWidget and StatefulWidget in Flutter?
--------------------------------------------------------------------------------
ANSWER:
- StatelessWidget: Immutable widget whose UI depends solely on configuration information passed to it at instantiation. Once built, it cannot change its internal state during runtime (e.g., PropertyCard, LoadingWidget).
- StatefulWidget: Mutable widget that maintains a persistent State object throughout its lifecycle. When internal state changes via setState(), Flutter schedules a rebuild of the widget subtree to reflect new data (e.g., SearchExploreScreen, ScheduledTimelineScreen).

--------------------------------------------------------------------------------
QUESTION 2: Explain the Flutter Widget Lifecycle for StatefulWidgets.
--------------------------------------------------------------------------------
ANSWER:
1. createState(): Called when Flutter creates a StatefulWidget to associate it with a State object.
2. initState(): Called exactly once when the State object is inserted into the Widget Tree. Used for stream subscriptions, controllers, and initializations.
3. didChangeDependencies(): Called immediately after initState() and whenever a dependency (like InheritedWidget or Theme) changes.
4. build(): Called multiple times whenever setState() is triggered, building the visual subtree.
5. dispose(): Called when the State object is permanently removed from the Widget Tree. Used to cancel stream listeners and dispose TextEditingControllers to prevent memory leaks.

QUESTION 3: Why did you use `runTransaction` in `BookingService` instead of simple Firestore `set()` or `update()`?
--------------------------------------------------------------------------------
ANSWER:
In a real-time booking app, multiple buyers might attempt to book the exact same viewing slot simultaneously. Simple writes create race conditions leading to double bookings. 
`_firestore.runTransaction()` reads the target slot's `isAvailable` property inside an atomic transaction. If another user reserved the slot milliseconds earlier, the transaction aborts and throws an exception. If available, it atomically sets `isAvailable = false` and creates the `bookings` document in one single, isolated operation.

QUESTION 4: What is the difference between `StreamBuilder` and `FutureBuilder` in Flutter?
--------------------------------------------------------------------------------
ANSWER:
- FutureBuilder: Listens to a single asynchronous operation (a Future) that completes once (e.g., logging in or fetching a single static profile document).
- StreamBuilder: Subscribes to a continuous stream of events (a Stream) that emits multiple asynchronous data snapshots over time. We used StreamBuilder with Cloud Firestore `snapshots()` in `BrowsePropertiesScreen` and `ScheduledTimelineScreen` so the UI automatically updates live whenever listings or bookings change in the cloud.

QUESTION 5: How does `LayoutBuilder` help achieve cross-platform responsiveness in HomeFind?
--------------------------------------------------------------------------------
ANSWER:
`LayoutBuilder` provides a BoxConstraints object containing `constraints.maxWidth` of the parent widget container. Based on the screen width at runtime:
- On Smartphones (< 550px): We set 1 column with a `childAspectRatio` of 0.86.
- On Tablets (550px - 899px): We set 2 columns with a ratio of 0.80.
- On Desktop/Wide screens (>= 900px): We set 3 to 4 columns with a ratio of 0.81.
This dynamic calculation prevents bottom pixel overflows on small screens and eliminates excess blank space under card buttons.

QUESTION 6: What is the `use_build_context_synchronously` lint warning and how is it safely handled?
--------------------------------------------------------------------------------
ANSWER:
When performing asynchronous operations (like `await _bookingService.bookViewing(...)`), the widget might unmount from the screen before the async operation finishes. Attempting to access `BuildContext` (e.g., showing a SnackBar or pushing a Route) on an unmounted widget causes a runtime error.
We handle this by checking `if (!mounted) return;` immediately after every `await` call before dereferencing `context` or `ScaffoldMessenger.of(context)`.

QUESTION 9: Explain the difference between Hot Reload (`r`) and Hot Restart (`R`) in Flutter.
--------------------------------------------------------------------------------
ANSWER:
- Hot Reload: Injects updated source code files directly into the running Dart VM without changing application state. Rebuilds the widget tree instantly while maintaining state variables.
- Hot Restart: Destroys the current state, resets the Dart VM to its initial state, re-initializes all singletons/services, and re-executes `main()`.

QUESTION 10: How does Flutter render widgets on Web and Desktop compared to Mobile?
--------------------------------------------------------------------------------
ANSWER:
- On Android/iOS: Flutter uses Skia/Impeller graphics engine to draw directly to a native canvas.
- On Chrome/Web: Flutter compiles Dart code into WebAssembly (Wasm) / JavaScript and uses CanvasKit (WebGPU/WebGL) or HTML/CSS renderers to draw pixel-perfect UI identical across mobile and desktop browsers.

QUESTION 11: What is the purpose of `InheritedWidget` and how is it used in `AppTheme`?
--------------------------------------------------------------------------------
ANSWER:
`InheritedWidget` is a low-level Flutter class that efficiently propagates data down the widget tree. When data in an InheritedWidget changes, descendant widgets that depend on it automatically rebuild. Flutter's `Theme.of(context)` and `MediaQuery.of(context)` use InheritedWidgets under the hood to supply our custom dark theme (`AppTheme.darkTheme`) and screen dimensions to all child screens.

QUESTION 13: What is the role of `clipBehavior: Clip.antiAlias` on custom decorated containers in HomeFind?
--------------------------------------------------------------------------------
ANSWER:
When a `Container` or `Card` has rounded corners (`BorderRadius.circular(24)`), child widgets (like `Image` or `TextField`) can bleed outside the rounded border, creating rectangular background artifacts. Applying `clipBehavior: Clip.antiAlias` clips all child rendering precisely to the rounded outer boundary for a sleek visual finish.

QUESTION 15: What are the key performance optimizations implemented in this codebase?
--------------------------------------------------------------------------------
ANSWER:
1. `const` Constructors: Widespread use of `const` widgets allows Flutter to reuse existing widget instances during rebuilds without re-allocating memory.

QUESTION 16: What is Dart, and why does Flutter use Dart instead of JavaScript or Java?
--------------------------------------------------------------------------------
ANSWER:
Dart is an object-oriented, strongly typed language developed by Google. Flutter chose Dart for several key reasons:
1. Dual Compilation: Dart supports AOT (Ahead-Of-Time) compilation to native machine code for production releases, and JIT (Just-In-Time) compilation for lightning-fast Hot Reload during development.
2. Single-Threaded Event Loop: Handles UI events and asynchronous I/O without the overhead or locks of traditional multi-threading.
3. Declarative UI Alignment: Memory allocation and garbage collection in Dart are optimized for creating and destroying thousands of ephemeral UI widget objects per second without stuttering.

QUESTION 17: What is the difference between Widget, Element, and RenderObject (The 3 Trees in Flutter)?
--------------------------------------------------------------------------------
ANSWER:
- Widget Tree: An immutable blueprint of the UI configuration defined in code. Rebuilt frequently whenever state changes.
- Element Tree: A persistent, mutable structural tree that manages the lifecycle of widgets and pairs each Widget with a RenderObject. Acts as the manager and reuses RenderObjects when possible.
- RenderObject Tree: The low-level rendering engine tree responsible for layout calculation (constraints down, sizes up), painting onto the canvas, and hit testing.

QUESTION 18: What is Sound Null Safety in Dart and how does it prevent runtime crashes?
--------------------------------------------------------------------------------
ANSWER:
Sound Null Safety ensures that variables cannot contain `null` unless explicitly marked as nullable using `?` (e.g., `String? name`).
- Compile-Time Protection: Null pointer errors are caught at compile-time instead of causing runtime crashes.
- Performance Optimizations: The Dart compiler produces smaller, faster binaries because non-nullable variables never need runtime null checks.
- Related Operators: `?` (nullable type declaration), `!` (null assertion operator), `??` (if-null fallback operator), `??=` (null-aware assignment), and `late` (lazy initialization / late assignment).

QUESTION 19: Explain the `main()`, `runApp()`, and `setState()` functions in Flutter.
--------------------------------------------------------------------------------
ANSWER:
- `main()`: The mandatory top-level entry point function for every Dart application where execution starts.
- `runApp(Widget app)`: Inflates the root widget, attaches it to the screen canvas, and builds the root Element and Render trees.
- `setState(VoidCallback fn)`: A method inside `State<T>` that notifies the framework that the internal state of a StatefulWidget has changed. It executes the synchronous callback and marks the widget subtree as dirty, scheduling a `build()` execution.

QUESTION 20: What are Keys in Flutter (`GlobalKey`, `UniqueKey`, `ValueKey`), and when should you use them?
--------------------------------------------------------------------------------
ANSWER:
Keys preserve state when widgets move around the widget tree or when items are added, removed, or reordered dynamically in a list.
- `ValueKey`: Identifies a widget using a specific value (e.g., property ID `ValueKey(property.id)`).
- `UniqueKey`: Generates an automatically unique identifier to force a widget state re-creation.
- `GlobalKey`: Provides access to another widget's State object across the app, or maintains widget state across subtree shifts (e.g., `GlobalKey<FormState>()` for form validation).

QUESTION 21: What is the difference between `mainAxisAlignment` and `crossAxisAlignment` in Flex widgets (Row & Column)?
--------------------------------------------------------------------------------
ANSWER:
- `mainAxisAlignment`: Controls item positioning along the primary axis (horizontal for `Row`, vertical for `Column`). Options include `start`, `center`, `end`, `spaceBetween`, `spaceAround`, and `spaceEvenly`.
- `crossAxisAlignment`: Controls item positioning along the perpendicular axis (vertical for `Row`, horizontal for `Column`). Options include `start`, `center`, `end`, `stretch`, and `baseline`.

QUESTION 22: Explain `async`, `await`, `Future`, and `Stream` in Dart asynchronous programming.
--------------------------------------------------------------------------------
ANSWER:
- `Future`: Represents a single asynchronous computation that will yield a value or error in the future.
- `Stream`: A continuous sequence of asynchronous events emitted over time (e.g., Firestore real-time snapshots).
- `async`: Keyword marking a function body as asynchronous, automatically returning a `Future`.
- `await`: Pauses execution within an `async` function until the targeted `Future` completes, returning the unwrapped result without blocking the UI thread.

QUESTION 23: What is the difference between `Navigator.push()` and `Navigator.pushReplacement()`?
--------------------------------------------------------------------------------
ANSWER:
- `Navigator.push()`: Pushes a new route onto the navigation stack above the current route. The user can press the back button to pop the route and return to the previous screen.
- `Navigator.pushReplacement()`: Replaces the current top route with a new route. The old route is disposed, preventing the user from returning to it via the back button (e.g., navigating from Login Screen to Main Navigation Screen).

--------------------------------------------------------------------------------
QUESTION 24: What is the difference between `Expanded`, `Flexible`, and `Spacer` inside a Row or Column?
--------------------------------------------------------------------------------
ANSWER:
- `Flexible`: Resizes a child along the main axis. By default (`fit: FlexFit.loose`), the child takes *up to* its flex share of space, but can be smaller if its intrinsic size is smaller.
- `Expanded`: Shorthand for `Flexible(fit: FlexFit.tight)`. Forces the child widget to expand and take up *all* remaining unallocated space along the main axis.
- `Spacer`: Creates an empty, invisible flex space that pushes adjacent widgets apart (equivalent to `Expanded(child: SizedBox())`).

--------------------------------------------------------------------------------
QUESTION 25: Explain Mixins in Dart and how they differ from Single Inheritance and Interfaces.
--------------------------------------------------------------------------------
ANSWER:
- Mixin: A class containing methods and fields that can be reused across multiple class hierarchies without requiring traditional subclassing. Applied using the `with` keyword (e.g., `class _MyState extends State<MyWidget> with SingleTickerProviderStateMixin`).
- Difference: Unlike single inheritance (`extends`), a Dart class can apply multiple mixins. Unlike interfaces (`implements`), mixins provide full concrete code implementations rather than abstract signatures.

--------------------------------------------------------------------------------
QUESTION 26: What is an `Isolate` in Dart, and how does it differ from traditional Threads?
--------------------------------------------------------------------------------
ANSWER:
- Dart code runs inside an **Isolate**—an isolated single thread of execution with its own private heap memory and event loop.
- Isolates share **no memory** with each other. Communication between isolates happens strictly by passing messages over message channels (`ReceivePort` / `SendPort`) or via helper functions like `compute()`.
- This architecture eliminates race conditions and shared-memory synchronization locks common in traditional multi-threaded programming.

--------------------------------------------------------------------------------
QUESTION 27: Explain the difference between `SizedBox`, `Container`, and `Padding` widgets.
--------------------------------------------------------------------------------
ANSWER:
- `SizedBox`: A lightweight layout box with fixed width/height. Does not support background colors, borders, or decorations (ideal for lightweight `const` layout gaps).
- `Container`: A composite widget combining layout, alignment, padding, margins, background colors/gradients, borders, border radii, shadows, and transformation.
- `Padding`: A dedicated single-purpose widget that adds inset padding whitespace around a child.

--------------------------------------------------------------------------------
QUESTION 28: What is `BuildContext` in Flutter, and why is it so important?
--------------------------------------------------------------------------------
ANSWER:
- `BuildContext` is a reference handle to the location of a widget within the framework's Element Tree.
- It provides access to contextual data and ancestor widgets higher up in the tree (e.g., `Theme.of(context)`, `MediaQuery.of(context)`, `Navigator.of(context)`, `ScaffoldMessenger.of(context)`).
- Every widget's `build()` method receives its own unique `BuildContext`.

--------------------------------------------------------------------------------
QUESTION 29: What is `IndexedStack` and how does it differ from a standard `Stack` or `PageView`?
--------------------------------------------------------------------------------
ANSWER:
- `IndexedStack`: Displays only one child widget at a time based on a given index from a list of children, keeping all non-visible children initialized in memory with their state fully preserved.
- `Stack`: Displays all children simultaneously layered on top of each other along the Z-axis.
- `PageView`: Enables swipeable page transitions between children, but disposes/rebuilds off-screen pages unless explicitly kept alive.

--------------------------------------------------------------------------------
QUESTION 30: Explain how `TextEditingController` and `FocusNode` work in Flutter forms.
--------------------------------------------------------------------------------
ANSWER:
- `TextEditingController`: Manages text content, selection range, and cursor position for input fields (`TextField` / `TextFormField`). Emits notifications when text changes and must be disposed in `dispose()` to prevent memory leaks.
- `FocusNode`: Manages keyboard focus state for an input widget. Allows programmatic focus requests (`focusNode.requestFocus()`), detecting focus changes, or advancing focus between form fields on keyboard submit.
